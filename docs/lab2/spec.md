# Специфікація: асистент по колекції документів

Автор: Артур Винокур · Дата: 2026-11-16 · Версія: v1

## 1. Задача й користувач
Хто користувач: Черговий тренер або працівник рецепції батутного залу «ZeroGravity Gym».
Яке питання він ставить і що робить із відповіддю: Питає точні внутрішні норми залу (ціни абонементів, ліміти ваги на сітках, правила стрибків у поролонову яму, коди збоїв турнікета `T-xxx`, штрафи за інвентар) і одразу називає клієнту правило з посиланням на документ (`[doc-XX]`).
Що він робить сьогодні без асистента: Шукає потрібний пункт вручну по десятку текстових файлів або пише старшому зміни — це займає 3–5 хвилин і затримує відвідувачів на вході.

## 4. Non-goals v1 (чого асистент НЕ робить)
- Не продає абонементи, не бронює шафки і не приймає оплату.
- Не зберігає історію переписки між запитами (кожен запит незалежний).
- Не шукає дані в інтернеті — працює виключно по файлах `doc-01`..`doc-10`.
- Не розпізнає фото, аудіо чи PDF-документи.

## 5. Обсяг v1
Входить:
- 10 текстових документів «ZeroGravity Gym» у `docs/lab2/corpus/`.
- Набір із 20 еталонних запитів `docs/lab2/golden/queries.jsonl` та валідатор `scripts/validate-golden.ts`.
- Замір базової лінії без пошуку (`docs/lab2/baseline.md`).
- Чанкінг та локальний індекс документів (`docs/lab2/indexing.md`).
- Гібридний пошук (BM25 + ембедінги) із цитуванням `[doc-XX]` (`docs/lab2/retrieval.md`).
- Субагенти з ізольованим контекстом і крос-модельний верифікатор (`docs/lab2/subagents.md`, `docs/lab2/verifier.md`, `docs/lab2/budget.md`).
- Власний MCP-сервер за специфікацією та підключення до CLI-агента і застосунку (`docs/lab2/mcp-spec.md`, `docs/lab2/mcp-integration.md`).

Не входить до v1, але передбачено на майбутнє:
- Перевірка залишку бонусів `GravityPoints` по живій базі клієнтів.
- Telegram-бот для інструкторів залу.

## 6. Критерії приймання
Кожен — твердження, яке перевіряється командою, тестом або файлом із числом.

| # | Критерій (перевірне твердження) | Чим перевіряється |
|---|---|---|
| A1 | `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` проходять без помилок | Прогін локально та в CI |
| A2 | `docs/lab2/golden/queries.jsonl` містить ≥ 20 запитів і проходить валідатор | `npx tsx scripts/validate-golden.ts` |
| A3 | `docs/lab2/spec.md` закомічено до першого коміту коду Лаб. 2, а в `.agent-log/*.jsonl` немає записів редагування `spec.md` | `git log` та `Select-String -Path .agent-log\*.jsonl -Pattern 'lab2/spec\.md'` |
| A4 | Верифікатор на іншій моделі щонайменше 1 раз зупинив злиття через знайдену помилку | Запис у `docs/lab2/verifier.md` та тести верифікатора |
| A5 | На наборі `queries.jsonl` точність із пошуком ≥ 80%, покриття цитатами ≥ 90%, відмови на `unanswerable` — 4 із 4 | `npx tsx scripts/run-eval.ts` і таблиця в `docs/lab2/eval-report.md` |
| A6 | MCP-сервер проходить тести безпеки і відповідає на виклики з агента кодування та застосунку | `npm test` і лог викликів у `docs/lab2/mcp-integration.md` |

Правило оцінювання відповіді:
- Звичайний запит зараховується як правильний, якщо відповідь містить очікуваний факт з еталона (число, тариф або код) та цитує документ із `must_cite` у форматі `[doc-XX]`.
- Запит із `tag=unanswerable` зараховується як правильна відмова, якщо асистент прямо пише, що в документах залу цього немає, і не вигадує правил.

## 7. Обмеження
Бюджет: Безкоштовні рівні `gemini-3.5-flash-lite` (Google API) та `inclusionai/ling-3.2-flash:free` (OpenRouter), бюджет на всю роботу ≤ $0.05.
Мережа в CI: Тести проходять без мережі.
Апаратні: Ноутбук на Windows без дискретного GPU (генерація великою локальною моделлю на CPU повільна, тому пошук працює локально, а відповіді генерує легка хмарна модель).
Часові: Заняття 05–08, подання до заняття 09.
