# Підключення MCP-сервера

## Бік 1 — агент кодування
- Який агент і версія: opencode (локально)
- Чому саме він (шлях за $0 чи наявна підписка): Повністю безкоштовний шлях, що дозволяє тримати персональні дані локально без відправки на сервери OpenAI/Anthropic.
- Де лежить конфігурація: opencode.json у корені репозиторію
- Конфігурація дослівно (значення секретів вирізано, лишилися посилання на змінні):
\\\json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "lab2-corpus": {
      "type": "local",
      "command": ["npx", "tsx", "src/mcp/server.ts"],
      "enabled": true,
      "environment": { "MCP_CLIENT_LABEL": "opencode" },
      "timeout": 5000
    }
  }
}
\\\
- Що викликано: etch_chunk та search_corpus
- Доказ: рядки source=\opencode\ (заглушка конфігурації перевірена) та source=\lab2-app\ у 	races/mcp-calls.jsonl

## Бік 2 — застосунок
- Де код клієнта: scripts/mcp-demo.ts
- Команда запуску: 
px tsx scripts/mcp-demo.ts "батут"
- Що викликано: обидва інструменти + один виклик за межею, щоб показати відмову (doc-99#0000)
- Доказ: рядки source=lab2-app у 	races/mcp-calls.jsonl, вивід команди.

## Чим відрізняються два боки
- Робоча тека і оточення процесу: opencode запускає процес зі свого робочого каталогу (зазвичай корінь), застосунок mcp-demo.ts — зі свого. Всі шляхи в MCP-сервері мають бути відносними до самого сервера.
- Таймаути клієнта проти таймауту сервера: opencode чекає список інструментів 5000 мс (задано в конфігу), тоді як внутрішній таймаут сервера на пошук — 10000 мс (LIMITS.timeoutMs).
- Що з цього я зафіксував у mcp-spec.md як вимогу, а не як випадковість: Вимогу доступу лише до закоміченого data/index.json та відсутність доступу до аргументів-шляхів від клієнта.

## Секрети
- Жодного значення ключа в закомічених конфігураціях: перевірено командою git status та відсутністю хардкоду в opencode.json.
- Де насправді лежать ключі: .env.local (проігноровано в git); у репозиторії є приклад .env.example без значень.
