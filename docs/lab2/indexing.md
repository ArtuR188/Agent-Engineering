# Індексація колекції

## 1. Колекція
- Документів: **10** (вимога: 10–40) · символів усього: **15 795** (27 648 байтів UTF-8 без BOM) · мова(и): **українська**
- Де лежить: `corpus/` (`corpus/doc-01.md`..`corpus/doc-10.md`) · як відтворюється: лежить у git та відтворюється скриптом `npx tsx scripts/generate-corpus.ts`
- Імʼя файлу = `id` документа зі `spec.md`: **так** (`corpus/doc-01.md` → `doc-01` .. `corpus/doc-10.md` → `doc-10`, точно збігається з `must_cite` у `docs/lab2/golden/queries.jsonl`)

## 2. Правило фрагментації і чому саме таке
- Межі: **за заголовками Markdown (`#`..`######`), а всередині довгих розділів — за порожнім рядком (`\n\n`), кінцем речення (`[.!?…»]\s`) або пробілом**
- Числа: максимум **900** симв., мінімум **180** симв., перекриття **90** симв.
- Чому: Кожен із 10 регламентів «ZeroGravity Gym» (`1354–1905` символів на файл) складається з 2–3 самостійних нормативних розділів `## N. ...` довжиною `450–824` символів (тарифні плани у `doc-01`, коди помилок `T-100..T-500` у `doc-04`, склад аптечок Сектора А і Б у `doc-08`). Орієнтири вендорів (OpenAI `800/400` токенів, приклад Google `200/20` токенів, Anthropic «кілька сотень токенів») враховано як зовнішні рамки, але поріг `maxChars = 900` обрано саме під довжину одного тематичного розділу нашої колекції (~130–160 слів українською), щоб не змішувати різні правила чи коди збоїв в один вектор і не різати таблиці посередині. Поріг `minChars = 180` приклеює короткі примітки до попереднього фрагмента того самого розділу, а `overlapChars = 90` (10% від максимуму, ≤ половини розміру) страхує від розриву умови й числового нормативу на стику абзаців.
- Що вийшло: фрагментів **36**, довжина — медіана **571**, мін **52**, макс **824** симв.
- Нормалізація тексту: `BOM прибрано, CRLF→LF, пробіли в кінці рядків прибрано` (`raw.replace(/^\uFEFF/, '').replace(/\r\n/g, '\n').replace(/[ \t]+$/gm, '')`)

## 3. Ембедінги
- Шлях: **Б: Gemini через AI SDK (`@ai-sdk/google`)** · чому саме цей: індекс у `data/index.json` має працювати у єдиному векторному просторі як локально, так і в задеплоєній серверлес-функції (Vercel), де `localhost:11434` локальної Ollama недоступний; водночас у `src/rag/embed.ts` реалізовано обидва шляхи (`geminiEmbedder`, `ollamaEmbedder`) та `fakeEmbedder` для CI без мережі.
- Модель із тегом або версією: `gemini-embedding-001` (заголовок індексу: `google:gemini-embedding-001@768`)
- Розмірність: **768** · taskType (для Gemini): `RETRIEVAL_DOCUMENT` (при індексації документів) та `RETRIEVAL_QUERY` (при пошуковому запиті)
- Якщо шлях Б: чому ці документи можна було надіслати на безкоштовний рівень, де вміст використовується для покращення продуктів провайдера: усі 10 документів є **100% синтетичним авторським текстом** для вигаданого залу «ZeroGravity Gym», опублікованим під відкритою ліцензією **CC0-1.0 (Public Domain)** без жодних персональних, медичних чи комерційних даних.

## 4. Індекс
- Де: `data/index.json` · розмір: **0.28 МБ** · у git: **так** (лежить у репозиторії для детермінованої перевірки в CI та серверлес-деплою)
- Чим шукається: `cosineSimilarity` з `ai`, повний перебір у памʼяті
- Чому не база: на масштабі 10 документів і 36 векторів по 768 вимірів (0.28 МБ JSON) повний перебір у памʼяті триває частки мілісекунди і не потребує нативних залежностей (`better-sqlite3`) або зовнішніх хмарних БД, які можуть заснути перед захистом.
- Час побудови: **5.4 с** на Windows 11 (Node.js v24.22.0) через Google AI Studio API (`gemini-embedding-001`, 768 вимірів)

## 5. Відтворюваність
- Команда перебудови: `npm run index`
- Повторний запуск дає: ті самі `id` (`doc-01#0000`..`doc-10#0002`), межі (`start`/`end`), шляхи заголовків (`heading`), хеші `sha256` і кількість фрагментів (**36**)
- Що саме НЕ побайтово однакове і чому: поле `builtAt` (мітка часу ISO-8601) та можливі відмінності в останньому (6-му) знаку після коми у числах з плаваючою крапкою векторів при обчисленні на різних GPU-вузлах API
- Перевірки в CI: `tests/chunk.test.ts`, `tests/index.test.ts` — виконуються повністю без мережі й без API-ключів

## 6. Що зберігається для цитування (вхід кроку 05)
`id` фрагмента (`doc-XX#NNNN`) → `docId` + `start`/`end` (0-based зсуви в нормалізованому тексті) + шлях заголовків (`heading`). Перевіряється тестом «кожен фрагмент розвʼязується назад у файл колекції» (`text.slice(c.start, c.end) === c.text`) та тестом незмінності `sha256` кожного документа.
